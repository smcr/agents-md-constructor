## Context

Конструктор уже грузит все Section/Rule/Tag, собирает превью через `assemblePreview` и открывает один попап из **Показать**. Список Rule на экране фильтруется по Tag (AND на Section и Rule). Инкремент `counter` вызывается только из **Показать**. См. proposal.md и delta specs `constructor` / `catalog`.

## Goals / Non-Goals

**Goals:**

- Один источник правды для «популярности»: среднее и фильтр считаются на сервере.
- Переиспользовать существующий попап и `assemblePreview`.
- Не трогать путь **Показать** (чекбоксы и `POST /api/rules/:id/counter`).

**Non-Goals:**

- Не менять схему БД и не трогать `Section.counter`.
- Не менять фильтр списка Section/Rule в левой/правой колонке.
- Не кэшировать среднее между запросами.

## Decisions

### 1. `GET /api/rules/popular` вместо расчёта на клиенте

Среднее берётся по **всем** approved Rule, а конструктор на экране показывает только часть. Клиентский расчёт по уже загруженному списку хрупок (неполный список, расхождение с будущими фильтрами API). Отдельный GET держит критерий в одном месте.

Альтернатива: считать среднее во фронте из `api.rules.list()`. Отклонено: дублирует правило и зависит от того, что список полный.

Маршрут регистрируется **до** `GET /:id`, иначе `popular` станет id.

Авторизация: GET уже публичный (`requireAuthForWrites` не применяется). Инкремента нет.

### 2. Query: повторяющийся `tag_id`

`GET /api/rules/popular?tag_id=1&tag_id=2` — каждый id обязателен (AND) и для Rule, и для его Section. Без параметров — только порог по среднему.

Альтернатива: `tag_ids=1,2`. Отклонено: существующий поиск уже использует `tag_id`.

### 3. Среднее в БД, сравнение строгое

`AVG(counter)` по `approved = true`, затем Rule с `approved = true`, Section `approved = true`, `counter > avg`. Если approved Rule нет — пустой список. Равенство среднему не проходит.

### 4. Превью на клиенте из ответа API

Кнопка **Часто выбирают** с классом как у **Показать** (`primary float-show`) стоит между **Показать** и **+**.

По клику: запросить popular с текущими `selectedTagIds`, собрать текст `assemblePreview(allApprovedSections, popularRules, popularIds)`, открыть тот же попап. Чекбоксы и `increment` не вызываются.

Альтернатива: подменить `selectedRuleIds` на время превью. Отклонено: сломает сохранённые чекбоксы.

## Risks / Trade-offs

- [Пустой превью при одинаковых counter] → ожидаемое поведение; отдельный empty-state не делаем (как у **Показать** без галочек).
- [Дробное среднее vs integer counter] → сравнение в SQL/`gt` по числу; равенство отсекается.
- [Длинная подпись кнопки на узком экране] → тот же `min-width`, что у **Показать**; при необходимости только CSS.

## Migration Plan

Схема не меняется. Выкат: задеплоить API и фронт вместе. Откат: убрать кнопку и маршрут; данные не портятся.
